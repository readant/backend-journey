## 项目一：企业官网 + CMS（bj-01-cms）

**业务定位**：企业官网展示 + 后台内容管理系统
**业务类型**：内容型业务
**学习阶段**：阶段一（语法锚定期）→ 阶段二（框架认知期）

### 功能模块与开发顺序

```
Phase 1：骨架搭建（第 1 周）
├── F1.1 项目初始化：Maven 项目结构、Spring Boot 启动类、application.yml
├── F1.2 公共基础：R 返回体、全局异常处理、基础配置
└── F1.3 Hello World 接口：第一个 @RestController，验证项目能跑

Phase 2：管理员与权限（第 2 周）
├── F2.1 管理员表设计：用户表建表、Entity、Mapper
├── F2.2 管理员 CRUD：新增/查询/修改/删除管理员
├── F2.3 登录接口：密码校验（BCrypt）、简单 Token 生成
└── F2.4 角色权限基础：角色表、管理员-角色关联、简单 RBAC

Phase 3：内容管理核心（第 3-4 周）
├── F3.1 栏目管理：多级栏目树结构、树形查询接口
├── F3.2 文章管理：文章 CRUD、草稿/发布状态、分页查询
├── F3.3 文章详情：富文本存储、封面图上传
├── F3.4 产品分类：产品分类树、产品 CRUD
└── F3.5 前台展示接口：首页聚合、栏目列表、文章详情（无鉴权）

Phase 4：完善与收尾（第 5 周）
├── F4.1 操作日志：AOP 切面自动记录操作日志
├── F4.2 接口文档：SpringDoc OpenAPI 配置
├── F4.3 数据字典：系统配置项管理
└── F4.4 项目复盘：整理速查卡片、总结项目一知识点
```

### 技术覆盖清单

| 技术点                       | 对应功能  |
| ---------------------------- | --------- |
| Java 语法全覆盖              | Phase 1-2 |
| Maven 依赖管理               | Phase 1   |
| Spring Boot 启动原理、IoC/DI | Phase 1-2 |
| MyBatis-Plus CRUD、分页      | Phase 2-3 |
| 条件构造器                   | Phase 3   |
| 参数校验                     | Phase 2-3 |
| 全局异常处理                 | Phase 1   |
| AOP（日志切面）              | Phase 4   |
| 文件上传                     | Phase 3   |
| SpringDoc OpenAPI            | Phase 4   |
| 树形结构设计                 | Phase 3   |

### 简历描述参考

> 独立设计并实现企业级 CMS 内容管理系统，支持多级栏目管理、文章发布、产品分类、RBAC 权限控制，采用 Spring Boot + MyBatis-Plus 分层架构，提供前台展示与后台管理分离的 RESTful API。

## 项目二：电商系统（bj-02-ecommerce）

**业务定位**：B2C 电商商城后端
**业务类型**：交易型业务
**学习阶段**：阶段二（框架认知期）→ 阶段三（实战加速期）

### 功能模块与开发顺序

```
Phase 1：用户体系（第 1-2 周）
├── F1.1 项目初始化：基于项目一经验快速搭建骨架
├── F1.2 用户注册/登录：手机号+验证码登录、JWT 鉴权
├── F1.3 Spring Security 集成：认证过滤器、权限注解
├── F1.4 收货地址管理：地址 CRUD、默认地址
└── F1.5 用户中心：个人信息修改、密码修改

Phase 2：商品中心（第 3-4 周）
├── F2.1 分类管理：多级分类树
├── F2.2 SPU/SKU 设计：商品SPU、SKU、规格属性建模
├── F2.3 商品 CRUD：商品发布、上下架、图片管理
├── F2.4 商品搜索：Elasticsearch 集成、全文检索
└── F2.5 商品缓存：Redis 缓存商品详情、缓存穿透/击穿处理

Phase 3：购物车与订单（第 5-7 周）
├── F3.1 购物车：Redis 存储、加购/修改/删除、合并购物车
├── F3.2 订单创建：下单流程、库存预扣减、订单号生成
├── F3.3 订单状态机：待支付→已支付→已发货→已完成→已取消
├── F3.4 超时取消：定时任务扫描未支付订单、库存回滚
├── F3.5 订单查询：用户订单列表、订单详情、分页
└── F3.6 事务一致性：订单+库存+扣款的事务处理

Phase 4：支付与营销（第 8-9 周）
├── F4.1 支付宝对接：沙箱环境、支付下单、支付回调
├── F4.2 退款处理：退款申请、退款回调
├── F4.3 优惠券（可选）：优惠券模板、领券、下单抵扣
└── F4.4 项目复盘：整理速查卡片、对比项目一架构演进

Phase 5：进阶能力（第 10 周，可选）
├── F5.1 短信通知：下单/发货短信通知
├── F5.2 异步解耦：下单后异步发短信（消息队列初步）
└── F5.3 接口限流：热点接口防刷
```

### 技术覆盖清单

| 技术点                             | 对应功能  |
| ---------------------------------- | --------- |
| JWT 鉴权                           | Phase 1   |
| Spring Security                    | Phase 1   |
| Redis 基础（String/Hash/List/Set） | Phase 2-3 |
| Spring Data Redis                  | Phase 2-3 |
| Elasticsearch                      | Phase 2   |
| 事务管理（@Transactional）         | Phase 3   |
| 定时任务（@Scheduled）             | Phase 3   |
| 设计模式：策略模式（支付）         | Phase 4   |
| 设计模式：模板方法（订单流程）     | Phase 3   |
| 第三方集成（支付宝）               | Phase 4   |
| 消息队列初步                       | Phase 5   |

### 简历描述参考

> 负责电商系统核心链路开发，设计 SPU/SKU 商品模型，实现基于 Redis 的购物车与缓存策略，完成订单状态机设计与支付宝沙箱支付对接，使用 Elasticsearch 实现商品全文检索，涉及事务一致性、定时任务、策略模式等核心技术。

## 项目三：社区/论坛（bj-03-community）

**业务定位**：兴趣社区（图文内容 + 社交互动）
**业务类型**：社交型业务
**学习阶段**：阶段三（实战加速期）

### 功能模块与开发顺序

```
Phase 1：用户与社交关系（第 1-2 周）
├── F1.1 项目初始化 + 用户体系（快速复用经验）
├── F1.2 个人资料：头像、昵称、简介
├── F1.3 关注系统：关注/取关、关注列表、粉丝列表
└── F1.4 个人主页：用户公开信息、帖子列表

Phase 2：内容发布（第 3-4 周）
├── F2.1 帖子发布：图文帖子、标签选择
├── F2.2 话题/标签：话题创建、标签管理
├── F2.3 帖子列表：按时间/热度排序、分页
└── F2.4 帖子详情：浏览量统计

Phase 3：互动系统（第 5-6 周）
├── F3.1 点赞：Redis Set 实现、点赞/取消
├── F3.2 评论系统：多级嵌套评论、评论列表
├── F3.3 收藏：收藏/取消、收藏列表
└── F3.4 计数器：点赞数、评论数、粉丝数（Redis 维护）

Phase 4：信息流与消息（第 7-8 周）
├── F4.1 关注 Feed 流：拉模式实现
├── F4.2 通知系统：评论通知、关注通知、系统通知
├── F4.3 消息队列：异步通知分发（RabbitMQ）
└── F4.4 内容审核：敏感词过滤（DFA 算法）

Phase 5：收尾（第 9 周）
├── F5.1 举报处理：举报接口、管理后台处理
├── F5.2 数据统计：每日新增、活跃度统计
└── F5.3 项目复盘
```

### 技术覆盖清单

| 技术点                       | 对应功能   |
| ---------------------------- | ---------- |
| Redis 社交数据结构           | Phase 1、3 |
| 消息队列（RabbitMQ）         | Phase 4    |
| 事件机制（ApplicationEvent） | Phase 4    |
| Feed 流架构设计              | Phase 4    |
| DFA 敏感词算法               | Phase 4    |
| 并发基础（线程池）           | Phase 3-4  |

### 简历描述参考

> 设计并实现社区系统核心功能，包括关注/Fan 社交关系、多级嵌套评论、基于 Redis 的点赞与计数器、Feed 流信息分发，使用 RabbitMQ 实现异步通知，敏感词过滤采用 DFA 算法。

# 项目间递进关系

```
项目一 CMS ──────→ 项目二 电商 ──────→ 项目三 社区 ──────→ 项目四 SaaS
  │                    │                   │                   │
  │ Java 语法从零学     │ 缓存/安全/事务     │ 社交/消息队列      │ 多租户/架构
  │ Spring Boot 入门    │ 设计模式初步       │ Feed 流设计        │ Docker 部署
  │ 分层架构建立        │ 第三方集成         │ 异步解耦           │ 权限体系完整
  │                    │                   │                   │
  └─ 基础代码复制到 →──┘ 独立演进 ──────→──┘ 独立演进 ──────→──┘ 独立演进
```

每个项目开始时，从上一个项目复制基础代码（R、异常处理、工具类等），然后独立演进。
