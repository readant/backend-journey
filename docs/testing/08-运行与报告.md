# 08 运行与报告

> 测试写得再好，也要会跑、会看报告、会和构建流程衔接。这一篇讲本仓库测试的运行方式与工具链。

## 1. 依赖配置（pom.xml）

`bj-01-cms/pom.xml` 只需一个依赖 —— `spring-boot-starter-test` 会带齐 JUnit 5 / Mockito / AssertJ：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-test</artifactId>
    <scope>test</scope>
</dependency>
```

内置版本由 Spring Boot 父 POM 统一管理，**不要手动加 junit / mockito / assertj 坐标**，避免版本冲突。

> 新增依赖属于高风险变更（见 `docs/standards/version-evolution.md`），动手前先确认。

## 2. 运行命令

```bash
# 项目一目录下
mvn test                    # 跑全部测试
mvn test -Dtest=CategoryServiceImplTest   # 只跑一个测试类
mvn test -Dtest=ArticleServiceImplTest#shouldThrow_whenNotFound   # 只跑一个用例（#后跟方法名）
mvn test -Dtest=*ServiceImplTest          # 通配符跑一组
```

常用场景：

| 场景 | 命令 |
| ---- | ---- |
| 写完一个测试类，快速验证 | `mvn test -Dtest=CategoryServiceImplTest` |
| 改完业务代码，全量防回归 | `mvn test` |
| 只跑失败的用例调试 | `mvn test -Dtest=AdminServiceImplTest#shouldThrow_whenPasswordWrong` |
| 提交前完整校验 | `mvn spotless:apply && mvn test` |

IDE 里也可以直接对测试类 / 单个方法右键运行，单个用例自包含（见 07 篇反模式四）所以可以放心单跑。

## 3. 测试报告

```
bj-01-cms/target/surefire-reports/
├── com.readant.cms.service.impl.ArticleServiceImplTest.txt   # 人类可读汇总
└── TEST-com.readant.cms.service.impl.ArticleServiceImplTest.xml  # CI 可解析
```

- 跑完 `mvn test` 后，`txt` 文件直接看结果：通过数、失败数、失败原因堆栈
- 失败用例的完整堆栈在 `txt` 文件末尾，排查首选
- 覆盖率报告后续项目引入 JaCoCo 时沉淀到这里

## 4. 与 Spotless 格式校验的衔接

测试代码同样受 Spotless 约束（规则：提交前 `mvn spotless:apply` + `mvn spotless:check`）：

```bash
mvn spotless:apply   # 自动格式化全部代码（含测试）
mvn spotless:check   # 校验通过才能提交
mvn spotless:apply && mvn spotless:check && mvn test   # 标准提交前流程
```

常见问题：格式化后 import 顺序 / 缩进变化导致 git diff 变大 —— 这是预期行为，先 `spotless:apply` 再写测试，避免提交时被格式化器改动淹没真实变更。

## 5. 完整提交前校验流程

```bash
# 1. 格式化（唯一权威，见 .cursor/rules/coding-java.mdc）
mvn spotless:apply
# 2. 格式校验
mvn spotless:check
# 3. 全部测试
mvn test
# 4. 按 git 规范提交（见 .cursor/rules/git-workflow.mdc）
```

## 6. 测试排错快速路径

| 现象 | 第一步动作 |
| ---- | ---------- |
| 用例失败 | 看 surefire-reports 的 txt 堆栈 → 定位到断言行 |
| `UnnecessaryStubbingException` | 删冗余 `when`（见 07 篇坑 1） |
| 打桩不生效 | 核对参数匹配器与调用参数（见 07 篇坑 2） |
| 测试启动超时 | 检查是否误用 `@SpringBootTest`（见 07 篇坑 4） |
| 格式校验不过 | `mvn spotless:apply` 后重跑 |
