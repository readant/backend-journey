# 测试经验沉淀

> 本目录沉淀 Java 后端项目的**测试实战经验**：从「为什么测、测什么」到「怎么写、怎么避坑」，全部来自 `bj-01-cms` 的真实测试代码，与 `.cursor/rules/testing-java.mdc`（测试硬约束）配合使用。
>
> 规则管「必须遵守的底线」，本目录管「理解原理 + 实战技巧 + 踩坑经验」。

## 两条使用路径

### 路径一：学习（没写过测试的人）

按编号顺序读一遍，02/03/04 三篇配合 `bj-01-cms/src/test/java/` 的真实测试类看：

```
01 心法（想清楚为什么）→ 02 JUnit（骨架）→ 03 Mockito（替身）→ 04 AssertJ（断言）
→ 05 Service 实战（对着 CategoryServiceImplTest 看）→ 06 公共组件（对着 RTest/TokenServiceTest 看）
```

### 路径二：场景速查（任何时候，按需查）

| 我现在要… | 去翻哪篇 |
| ---- | ---- |
| 写一个**新的 Service 测试** | 05（照 6 种场景模板抄）+ 02/03/04 卡住时 |
| 写**公共组件 / 工具类**的测试 | 06 |
| 测试**报错、Mock 不生效、用例不隔离** | 07（坑 1~5）+ 08 第 6 节排错表 |
| 跑测试、看报告、提交前校验 | 08 |
| **改完代码 / 加了新功能**，不知道测哪些 | 10（先按影响面表自查） |
| **让 AI 帮**做联调测试 | 09（先定四边界，再下指令） |
| 忘了 `when` / `verify` / `assertThat` 怎么写 | 03 / 04 的语法速查表 |

## 维护规则（文档怎么扩容）

这套文档要长期跟随项目演进，**新增内容先找归属，找不到归属才开新篇**：

| 新内容是什么 | 写到哪里 |
| ---- | ---- |
| 踩了一个新坑（现象 → 原因 → 解法） | 07 追加「坑 N」 |
| 学到一个新测试技巧 / 新场景 | 对应的 02~06 篇章追加小节 |
| 覆盖率报告 / 测试数量变化 | `docs/coverage/`，不动本篇 |
| 集成测试（起 Spring 容器、连 Redis/ES） | 后续项目引入时开新篇 **11** |
| 前端测试（Vue 组件 / E2E） | 前端仓库自己的文档，不写这里 |
| 命令、报告、工具链变化 | 08 |

开新篇的门槛：**内容无法归入 01~10 任何一篇**（新主题域，如集成测试），且至少能写出一个完整主题。编号接着 10 往后排，README 分组表同步更新。
