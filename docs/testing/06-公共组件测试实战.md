# 06 公共组件测试实战

> 公共组件（工具类、异常处理器、无依赖 Service）没有 Mapper 可以 Mock，测法更「裸」：**直接 new 真身 + 纯断言**。这一篇覆盖本仓库 `common` 包下三类组件的测试方式。
>
> 完整源码对照：`bj-01-cms/src/test/java/com/readant/cms/common/` 下的 `RTest`、`GlobalExceptionHandlerTest`、`TokenServiceTest`。

## 1. 总原则：能 new 就 new

公共组件通常无外部依赖，**不需要 @Mock / @InjectMocks**，直接构造真身：

```java
@DisplayName("TokenService 单元测试")
class TokenServiceTest {

    private final TokenService tokenService = new TokenService();

    // ... 直接用真身测
}
```

这和 Service 测试的本质区别：**没有依赖需要替身，测的就是纯逻辑本身**。

## 2. 工具类 / 无状态组件（TokenService）

TokenService 内部用内存 Map 存 token，测它的行为契约：

```java
@Test
@DisplayName("生成 Token 并关联管理员ID")
void shouldCreateAndMap() {
    String token = tokenService.createToken(42L);

    assertThat(token).isNotBlank();
    assertThat(tokenService.validateToken(token)).isTrue();
    assertThat(tokenService.getAdminId(token)).isEqualTo(42L);
}

@Test
@DisplayName("每次生成不同 Token（随机性）")
void shouldGenerateUniqueTokens() {
    String token1 = tokenService.createToken(1L);
    String token2 = tokenService.createToken(1L);

    assertThat(token1).isNotEqualTo(token2);
}

@Test
@DisplayName("移除后 Token 失效")
void shouldInvalidateAfterRemove() {
    String token = tokenService.createToken(7L);

    tokenService.removeToken(token);

    assertThat(tokenService.validateToken(token)).isFalse();
    assertThat(tokenService.getAdminId(token)).isNull();
}
```

实战技巧：

- **状态依赖型组件**（有内部 Map）也要测「状态流转」：创建 → 验证 → 移除 → 再验证
- 随机性也值得测（`isNotEqualTo`），防止以后被改成固定值
- 不存在的 key 访问要断言安全（`isNull` / `isFalse`），锁定「查无返回 null 而非抛异常」的契约

## 3. 全局异常处理器（GlobalExceptionHandler）

异常处理器是「输入异常 → 输出 R」的纯映射，**是最好测的组件之一**：

```java
class GlobalExceptionHandlerTest {

    private final GlobalExceptionHandler handler = new GlobalExceptionHandler();

    @Test
    @DisplayName("业务异常 → 返回对应错误码和消息")
    void shouldMapBusinessException() {
        BusinessException e = new BusinessException(401, "用户名或密码错误");

        R<Void> result = handler.handleBusinessException(e);

        assertThat(result.getCode()).isEqualTo(401);
        assertThat(result.getMsg()).isEqualTo("用户名或密码错误");
        assertThat(result.getData()).isNull();
    }

    @Test
    @DisplayName("无字段错误 → 返回默认提示")
    void shouldReturnDefaultMsg_whenNoFieldError() {
        BindingResult bindingResult = mock(BindingResult.class);   // 关键技巧
        when(bindingResult.getFieldError()).thenReturn(null);
        MethodArgumentNotValidException e = new MethodArgumentNotValidException(null, bindingResult);

        R<Void> result = handler.handleValidationException(e);

        assertThat(result.getCode()).isEqualTo(400);
        assertThat(result.getMsg()).isEqualTo("参数校验失败");
    }
}
```

实战技巧 —— **mock 框架自己抛出来的异常**：

`MethodArgumentNotValidException` 这种 Spring 异常，构造时需要 `BindingResult`。我们不想真的触发一次参数校验，所以：

```java
BindingResult bindingResult = mock(BindingResult.class);
when(bindingResult.getFieldError()).thenReturn(fieldError);
MethodArgumentNotValidException e = new MethodArgumentNotValidException(null, bindingResult);
```

把 `BindingResult` 换成替身，再指挥它的 `getFieldError()` 返回想要的 `FieldError`，就能构造出「有字段错误 / 无字段错误」两种输入。`FieldError` 本身也可以 mock 或用真构造器。

## 4. 统一返回体（R）

纯静态工厂方法，测每组方法的契约：

```java
@Test
@DisplayName("成功 → code=200, msg=success")
void shouldReturnSuccess() {
    R<String> result = R.success("data");

    assertThat(result.getCode()).isEqualTo(200);
    assertThat(result.getMsg()).isEqualTo("success");
    assertThat(result.getData()).isEqualTo("data");
}
```

三个方法三组用例，锁定 code / msg / data 三个字段的约定 —— **这是全项目接口返回的契约，必须测**。

## 5. 什么样的组件不用测

| 不测 | 原因 |
| ---- | ---- |
| Spring 配置类（`MyBatisPlusConfig`、`WebMvcConfig`） | 框架行为，测了等于测框架 |
| Lombok 生成的 getter/setter/toString | 编译器生成的机械代码 |
| 纯数据库迁移脚本（Flyway） | 集成测试范畴 |
| 简单 CRUD 的 Mapper | 无业务逻辑，MyBatis-Plus 封装 |

## 6. 覆盖优先级回顾

```
✅ 必须覆盖  Service 层核心业务逻辑
✅ 建议覆盖  公共组件（R / GlobalExceptionHandler / TokenService —— 全项目契约所在）
⚠️ 可选     Mapper
❌ 不需要   Spring 配置类 / Lombok 方法
```

判断标准一句话：**「这个组件的输出有没有被全项目依赖？有，就测。」** 返回体、异常映射、Token 失效规则都是。
